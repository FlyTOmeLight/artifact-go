# 租户系统拥有 bucket 创建流程，artifact-go 暂时承载存储创建能力

每个租户独占一个 bucket，创建流程由租户系统触发。由于 storage 尚未独立，artifact-go 暂时提供 bucket 创建能力，后续将其迁入独立 storage 服务；文件登记与版本发布不会隐式创建 bucket。这样保留租户生命周期的职责归属，同时满足当前部署形态；租户系统通过内部 HTTP 接口及配套 Go SDK 调用；创建能力与文件/版本模块分开，便于后续迁出。bucket 名由 TenantID 按固定规则生成，不维护逐租户配置映射或映射表；历史文件保存登记时的完整位置。内部创建接口复用接入层的服务间鉴权，只有经其确认的租户系统身份可调用；storage不维护独立管理token。按当前租户ID契约使用固定命名v1：t_<24hex>到tenant-t-<24hex>。同租户创建按确定名称幂等，后端冲突必须确认可访问归属，不能一律当成功；接口及实施规则见代码结构设计。


2026-10-15 补充：临时 storage 模块现在同时承担通用文件能力，职责见 [ADR 0003](0003-storage-file-ownership.md)。租户系统仍只负责触发 bucket 创建；普通文件路由使用用户可信身份，bucket 管理路由独立使用 TenantServiceVerifier。首期同进程同库，不声称未来仅移动目录即可独立部署。
