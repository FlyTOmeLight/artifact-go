# 客户端直传对象存储，统一使用 S3 协议

状态：直传与 S3 决策继续有效；2026-10-15 的模块职责由 [ADR 0003](0003-storage-file-ownership.md) 更新。

文件字节由客户端直接上传到 S3 对象存储，multipart 的切分、并发、重试、完成及主动中止由客户端 SDK 编排，服务不维护 UploadID、part 清单或进度。本地部署同样通过 S3，取消服务自身的原生 local 后端；JuiceFS 内部使用何种数据后端是存储部署事项。

storage 模块负责文件登记、限定租户 bucket/key/操作/期限的短期上传凭证、存在和大小确认、读取授权及回收；artifact 只拥有版本发布、文件清单、可见性与保留决定。读取由客户端通过统一grant取得限权STS后直接访问S3，不代理文件流，不设上传或下载会话。实际后端必须通过所需 S3/STS、CORS 与回收契约验收，部署存在不等于能力已通过。

发布冻结数据库中的 JSON 快照和文件清单。客户端发布后修改外部对象自行负责；服务不强制防覆盖、不复制封存、不在发布时撤回旧上传凭证，也不持续监测或恢复已发布对象。文件确认后停止新上传授权，原凭证自然到期；临时文件及释放文件的正常回收由 storage 执行，未完成分片依赖客户端 Abort 或经过验证的存储生命周期。

一个租户对应一个 bucket，同租户项目共用。可信 TenantID 决定 bucket，客户端不能选择任意位置；StorageFile 保存 BackendID、Bucket、ObjectKey，后续所有存储操作使用原位置。

这使文件传输不依赖版本 API 副本生命周期，也让版本业务与通用存储分开。代价是客户端需要可达的 S3 端点，后端必须支持限权授权，文件绑定/释放需要明确交接规则。
