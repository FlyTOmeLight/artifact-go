日期：2026-10-15。状态：T00调查与本轮验证完成，建议已由用户全部批准；仍未通过的接入项见下表与存储报告。本报告记录T00调查时点；随后用户批准同步设计/Spec、初始化Git并开始T01。T00没有业务实现；后续进展由实施计划记录。

## 已确定与建议

**HTTP/JSON已确认。** 首期combined也通过回环HTTP交接，分离部署更换端点与认证配置，不再保留“现在本地直调、拆分再换RPC”的方案。业务事务、引用终态、补偿窗口及27个公开操作保持原契约。

| 事项 | 本次具体建议 | 实际依据 / 未完成边界 |
| --- | --- | --- |
| 仓库基线 | 已批准在当前目录原地初始化Git，首份提交纳入确认后的设计及必要部署/探针；忽略临时材料 | 本地无.git，远端tree返回409空仓库；没有需要迁移的旧业务代码 |
| 用户身份 | 保留注入resolver，由租户接入层验证用户和精确scope并返回active/deleted；测试显式注入fixture | 现有session/check不返回scope；用户Bearer验证、历史deleted scope授权仍缺完整接入，不能把403当deleted |
| 服务身份 | 分别配置artifact→storage与tenant→storage Bearer Secret，认证映射稳定consumer及精确scope allowlist | 复用现有server-go认证机制，既有鉴权测试通过；本项目凭证与轮换尚未部署 |
| 内部线协议 | 四个内部HTTP操作；scope是批级条件，响应数组；Bind/Release每批原子 | 文档及JSON示例已检查；内部handler和两库故障测试归T09，未冒充运行通过 |
| 本地容量及期限 | 1GiB单文件、1000文件清单、准备24小时；STS具体期限见配置稿 | 数值是开发建议，非生产配额；10GiB PVC不是硬限额，JuiceFS逻辑容量9GiB |
| failed任务恢复 | 维护命令以CAS只重排failed，保留载荷/NotBefore，审计与重排同事务 | 复用两域任务行，不新增公共task接口；T04后才有数据库行为可验证 |
| 存储与直传 | 采用当前JuiceFS；按实际policy长度拆grant批次，禁止通配资源兜底 | 普通IAM精确多key及读写正反例通过；真实到期后PUT被InvalidAccessKeyId拒绝，当前锁定源码支持该过期映射；临时用户/策略/对象清理通过 |

真实到期测试已等待900秒：到期后的STS请求被拒绝，随后服务身份对同key写入成功。原机器报告按严格错误码匹配标fail，保留不改；这不表示后端接受过期凭证。锁定源码的凭证查找会把已过期身份映射为InvalidAccessKeyId，与实际拒绝一致。本次没有临近截止的同STS正例，不声称验证了精确秒级边界；实际浏览器/容器SDK流程及自动回收worker仍待验收，不能把本轮基础协议通过等同于T08/T12整体验收。

## 一致性检查范围

已同步本地技术设计、代码结构、引用交接设计和流程HTML中的传输选择；引用交接客户端与内部controller的文件职责已补入代码结构。公开登记/确认仍是顶层数组；grants及业务files保持原结构；HTTP交接没有加入artifactID/versionID/draftID、共享事务或客户端额外步骤。

交叉检查修正了三处提案问题：失败预算只累计可确认执行错误，正常等待不扣；同机回环开发HTTP与生产TLS规则统一；内部错误对象和413错误名复用现有标准。任务恢复字段及具体路由已批准，尚未实现。
