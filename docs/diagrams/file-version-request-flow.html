ARTIFACT-GO / 设计 REVIEW

四种发布方式，
共用一套文件接口。

登记和确认直接接收、返回数组。单文件传一项，多文件和文件夹传多项；grant 保留权限参数，最后由 artifact 一次发布版本清单。

设计展示 · 尚未实现 · 草稿保存 JSON 与文件清单

前提：租户 bucket 和集合 a01 已存在，所有请求经可信身份解析，文件与集合在同一租户 / 项目作用域。以下 ID、凭证和响应均为示例 / 节选。

预览或下载：仍使用同一个 grant 接口
读取只传 fileIDs、scope 与 ttlSeconds。storage 校验可信租户 / 项目身份、文件归属与状态，不查询版本或草稿。未过期 ready 文件可在保存草稿前预览，bound 文件可读；uploading / deleting / deleted 不签发新读取权限。同作用域、同后端的不同版本或草稿文件可合并申请。一份 STS 覆盖本批精确 key，响应 actions 为 ["s3:GetObject"]；客户端用 S3 SDK GetObject / HeadObject 读取。ready 的授权到期时间不得超过准备 ExpiresAt，bound 不受历史准备期限限制。读取不延长准备期限、不延缓回收，也不保证对象一直存在到凭证到期。


单文件无草稿发布
登记文件
POST /v1/storage/files
[
  {
    "requestKey": "prepare-f01",
    "size": 1048576,
    "contentType": "application/octet-stream"
  }
]
[
  {
    "requestKey": "prepare-f01",
    "fileID": "f01",
    "state": "uploading",
    "error": null
  }
]
请求直接传 1–1000 项对象数组，单文件传一项；HTTP 200 直接返回等长、同序的逐项结果数组，每项含成功结果或 error。无效 JSON、非数组、空数组、超限、元素非对象或批内重复 requestKey 返回整请求 400，均不执行任何项；非 200 返回统一错误对象。每项 requestKey 独立幂等，字段值或文件处理失败记入该项 error，重试仅补失败项；不接收逻辑路径。
申请上传权限
POST /v1/storage/grants
{
  "fileIDs": [
    "f01"
  ],
  "scope": {
    "preset": "upload"
  },
  "ttlSeconds": 900
}
{
  "credentials": {
    "accessKeyID": "<temporary-key>",
    "secretAccessKey": "<temporary-secret>",
    "sessionToken": "<temporary-token>"
  },
  "endpoint": "https://s3.example.test",
  "region": "us-east-1",
  "forcePathStyle": true,
  "expiresAt": "<actual-expiry>",
  "actions": [
    "s3:AbortMultipartUpload",
    "s3:ListMultipartUploadParts",
    "s3:PutObject"
  ],
  "files": [
    {
      "fileID": "f01",
      "bucket": "tenant-t-aaaaaaaaaaaaaaaaaaaaaaaa",
      "objectKey": "files/f01"
    }
  ]
}
fileIDs 数组含 1–1000 项，同一批使用同一组 S3 Actions，整体校验通过后 HTTP 200 返回一份 STS；任一文件或权限不允许则整份失败。仅 uploading 且准备期限未到的文件可申请写权限；ready / bound 不续发写权限。只授权这些精确 ObjectKey，策略过大必须拆批，不能扩大到目录或 bucket。900 秒是申请值，实际有效期取请求、配置、文件准备期限与签发方上限的最小值。
直传文件字节
S3 SDK：PutObject 或 multipart
使用 grant.credentials 配置 S3 SDK，遍历 grant.files：
PutObject(file.bucket, file.objectKey, 对应本地字节)

大文件：
CreateMultipartUpload → UploadPart（并发/重试）
→ CompleteMultipartUpload
S3 保存完整对象。
文件数据库状态此时仍为 uploading。
同一批文件共用一份 STS，使用返回的每个 file.objectKey；不使用 model.bin 或目录相对路径作为物理 key。客户端控制并发、分片和断点恢复；上传流不经过业务 API。
确认文件就绪
POST /v1/storage/files/complete
[
  "f01"
]
[
  {
    "fileID": "f01",
    "state": "ready",
    "size": 1048576,
    "error": null
  }
]
请求直接传 1–1000 项 FileID 字符串数组；HTTP 200 直接返回等长、同序的逐项结果数组，每项含确认结果或 error。无效 JSON、非数组、空数组、超限、元素非字符串或批内重复 FileID 返回整请求 400，均不执行任何项；非 200 返回统一错误对象。storage 核对对象存在及实际大小，文件错误逐项返回并可重试；ready / bound 的确认重试返回原确认记录，不改变引用。uploading 文件不能进入草稿或版本清单。确认成功后可用 grant 的 download 预设预览，无需先保存草稿；ready 必须仍在准备期限内，读取不会延长期限。
发布正式版本
POST /v1/artifacts/a01/versions
{
  "requestKey": "publish-files-001",
  "payload": {
    "framework": "pytorch"
  },
  "files": [
    {
      "path": "model.bin",
      "fileID": "f01"
    }
  ]
}
{
  "id": "v01",
  "artifactID": "a01",
  "number": "1",
  "state": "ready",
  "files": [
    {
      "path": "model.bin",
      "fileID": "f01",
      "size": 1048576
    }
  ]
}
服务端先保存新增引用计划，再由 storage 独立提交 Bind；全部确认后，在 artifact 本地事务创建 Version、冻结 VersionFile 清单、更新编号与 alias、记录成功回执及旧引用释放任务。业务失败不发布版本，已绑定引用按持久补偿计划稍后释放。可引用同作用域内未过期 ready 或已有引用的 bound 文件，无需复制字节。成功重试使用原 requestKey 与原参数；客户端不调用 Bind / Release。

保存 JSON 与文件
PUT /v1/artifacts/a01/drafts/d01
{
  "requestKey": "save-draft-001",
  "expectedRevision": 1,
  "payload": {
    "model": "model-a",
    "temperature": 0.3
  },
  "annotations": {},
  "files": [
    {
      "path": "model.bin",
      "fileID": "f01"
    }
  ]
}
{
  "appliedRevision": 2,
  "draft": {
    "id": "d01",
    "revision": 2,
    "payload": {
      "model": "model-a",
      "temperature": 0.3
    },
    "annotations": {},
    "files": [
      {
        "path": "model.bin",
        "fileID": "f01",
        "size": 1048576
      }
    ]
  }
}
PUT 必须传 requestKey、expectedRevision、JSON、annotations 和完整 files 清单。服务端先持久记录计划并 Bind 新引用，再本地 CAS 提交完整草稿、appliedRevision 和旧引用释放任务；未变文件沿用引用。RevisionConflict 409 表示本次已中止：保留本地编辑、暂停自动保存与发布，不得只换 Revision 覆盖。RequestInProgress 409 / OperationOutcomeUnknown 503 要以原键原参数核对结果。成功重试的 appliedRevision 仍为 2，但 draft 可能是更新的完整快照，不得把旧请求内容配上新 Revision。
刷新恢复附件
GET /v1/artifacts/a01/drafts/d01
刷新或重新打开同一个 DraftID，不创建新草稿。
{
  "id": "d01",
  "revision": 2,
  "payload": {
    "model": "model-a",
    "temperature": 0.3
  },
  "annotations": {},
  "files": [
    {
      "path": "model.bin",
      "fileID": "f01",
      "size": 1048576
    }
  ]
}
服务端返回同一修订的 JSON 与文件清单，客户端恢复已保存附件。尚未 complete / 绑定的文件受准备期限约束。失败 attempt 已绑定的附件由补偿任务释放，不早于原准备期限；任务延迟可能保留更久，不重置准备 TTL。草稿不自动过期。预览使用 POST /v1/storage/grants，只传 fileIDs、scope={preset:"download"} 与 ttlSeconds；storage 按可信身份、文件归属和自身状态授权，不检查草稿清单。尚未保存的未过期 ready 文件也可预览，再使用返回的 STS 直接向 S3 读取。

请求直接传 1–1000 项对象数组，单文件传一项；HTTP 200 直接返回等长、同序的逐项结果数组，每项含成功结果或 error。无效 JSON、非数组、空数组、超限、元素非对象或批内重复 requestKey 返回整请求 400，均不执行任何项；非 200 返回统一错误对象。每项 requestKey 独立幂等，字段值或文件处理失败记入该项 error，重试仅补失败项；不接收逻辑路径。

重复、乱序与删除回执
同一 (ConsumerID, ReferenceID) 固定对应一个 FileID 和作用域；重复 Bind / Release 幂等。Release 先到也记录 released 墓碑，后到的 Bind 永久拒绝。仅写墓碑不把未绑定的准备文件转 deleting；文件锁决定 Bind、Release 与 GC 谁先成功。
版本或草稿的内部 ReferenceID 不进入客户端授权参数。服务端通过 GetReferenceStatuses 确认释放：非最后引用完成即收尾，最后引用按物理删除回执收尾。删除不是即时撤销凭证，读取权限仍按 storage 自身状态判断。


scope：使用预设，或直接传 S3 Actions
预设S3 Actions允许的操作
uploads3:PutObject, s3:ListMultipartUploadParts, s3:AbortMultipartUpload普通上传、创建 / 上传 / 完成分片、列出已上传分片、中止分片上传
downloads3:GetObject下载、Range 读取和 HEAD 查询
scope.preset 与 scope.actions 必须二选一。自定义权限直接使用 S3 原名；服务端按允许的 Actions、调用者权限和文件状态校验，不能因为客户端指定了 Actions 就直接授权，也不静默删减权限。响应 actions 返回展开后的实际权限。不同权限的文件分别申请；续期再次调用同一个接口并重新校验。

{
  "fileIDs": [
    "f01",
    "f02"
  ],
  "scope": {
    "actions": [
      "s3:PutObject",
      "s3:ListMultipartUploadParts",
      "s3:AbortMultipartUpload"
    ]
  },
  "ttlSeconds": 900

本例自定义 actions 与 upload 预设等价。s3:PutObject 同时覆盖普通上传与分片创建、上传、完成；s3:GetObject 同时允许 GET 与 HEAD。读取仅允许未过期 ready 或 bound 文件，写入仅允许未过期 uploading 文件。混合读写 Actions 必须同时满足状态条件，首期没有同时允许新读写授权的文件状态，因此整份拒绝。对象删除继续由引用释放与后台回收负责。
