# 2026-10-15 实际对象存储契约结果

> 历史验证记录：原 RustFS + JuiceFS 环境及随后独立运行的 JuiceFS + Redis 环境均已退役。当前安装与访问见 [Forge 部署说明](../../deploy/forge/README.md)。以下记录保留当时版本与环境的实际结果。用户后续已取消防覆盖要求，原条件写失败不再是当前契约阻塞；最新验收边界见[验证指南](README.md)。

当时隔离部署的基础数据通路可用，**尚不满足 artifact-go 的客户端直传契约**。RustFS 的缺口是存储策略无法强制完整对象写入包含 `If-None-Match: *`；JuiceFS gateway 还缺少可信校验和条件写语义，不能将它作为已通过任务 02 的对象存储入口。

部署位于本机 OrbStack 的 `artifact-storage` namespace，RustFS 1.0.1、JuiceFS 1.4.1（构建 `2026-07-30.0b90c7d`）。实际测试通过 localhost 转发，RustFS `http://127.0.0.1:19000`、JuiceFS gateway `http://127.0.0.1:19010`，region `us-east-1`，path-style，专用 bucket `artifact-contract`、每次 UUID 子前缀。外网客户端路径及浏览器仍未验收。持久化和 10 GiB SSD 配置见 [部署说明](../../deploy/storage/verification-20261014.md)。

## RustFS 原生入口

| 能力 | 结果 | 实际证据 |
| --- | --- | --- |
| 单次上传、读取流提前关闭、删除不存在对象 | pass | 正例 PUT/GET、提前 close、重复 DELETE 实际成功 |
| 限 key STS、实际截止时间 | pass | root 派生会话只能上传指定 key，other key、完整对象删除、读取 bucket policy 被拒绝 |
| 普通 IAM 用户签发 STS | pass | 独立只允许测试前缀上传/列分片/中止的普通用户，实际上传成功、other key/delete 拒绝 |
| 普通验证 IAM 用户及其 policy 清理 | pass | finally 删除两者，密钥仅在进程内存中，未写 profile 文件 |
| 单次 SHA256 校验 | 部分通过 | 错误 checksum 被 BadDigest 拒绝；HEAD 可取得 SHA256，但缺失 ChecksumType，探针按严格契约记录 fail |
| 两片 SHA256 COMPOSITE 上传 | pass | 每片 checksum、ListParts、Complete、HEAD 的组合值、类型及大小均一致；组合值保留 `-2` |
| 正确条件头拒绝旧授权覆盖 | pass | PUT 与 Complete 均拒绝 `If-None-Match: *` 覆盖已有对象 |
| 存储强制不可覆盖 | **fail** | 省略条件头时，PUT 和 Complete 对新 key 与已有 key 都成功；独立复核使用不同字节，读取明确得到修改后内容 |
| 条件写策略配置 | **fail** | 部署尝试配置 `s3:if-none-match` 条件被 RustFS 1.0.1 以 InvalidArgument 拒绝；不能用客户端习惯带条件头替代强制策略 |
| Versioning | pass | 实际配置 Disabled；不推导 Enabled/Suspended 下的物理回收能力 |
| 未完成分片生命周期 | 配置 pass、执行 pending | 配置符合会话期限；尚无到期后实际后台回收证据 |
| CORS | 修正后配置 pass、浏览器 pending | 原配置 ExposeHeaders 仅 ETag；补齐 SHA256/type 暴露头后已独立复核，实际浏览器流程未执行 |
| 凭证实际到期失效 | 拒绝已观测、原因 pending | 已等待真实 Expiration 后再请求，后端返回 InvalidRequest 并拒绝；该码不是明确过期错误，尚不能确认拒绝原因就是到期 |

CORS 修正后的独立快照见 [cors-after-fix.json](cors-after-fix.json)。原生完整探针的 CORS fail 对应修正前配置，保留为历史验证快照；此次配置修正不改变不可覆盖失败的结论。

主代理另用同一仍有效的 exact-key STS 凭证，先带条件头上传 original，再省略条件头上传不同字节，服务读取确认内容已改变；测试对象已删除并确认 404。该证据直接证明可覆盖完整对象，而不仅是重复相同内容的请求成功，见 [overwrite-distinct-content.json](overwrite-distinct-content.json)。

普通 IAM 路径的无凭证机器报告见 [temporary-iam-report.json](temporary-iam-report.json)。原生完整探针报告见 [rustfs-report.json](rustfs-report.json)，该最终报告包含完整到期等待后的结果。其 credential_expiration 的 fail 是预期错误码不匹配，不能解释为已证实后端接受过期凭证；请求确实被拒绝，具体失效原因仍 pending。

单次 HEAD 缺失类型还需要确定 Adapter 是否可根据存储的明确协议保证识别 FULL_OBJECT；本次没有自行补写类型并将其标为通过。分片 SHA256 组合校验不能当作全文件 SHA256。

## JuiceFS gateway 独立入口

| 能力 | 结果 | 实际证据 |
| --- | --- | --- |
| 单次/分片正例、读取流关闭、列举/中止分片、删除不存在对象 | pass | 使用现有 gateway 服务身份完成实际请求，探针对象已清理 |
| 限权 STS | pending | root 身份请求返回 403 AccessDenied，理由是该请求不允许生成临时凭证；未将此身份限制判为 gateway 全部身份不支持 STS |
| 单次/分片不可覆盖 | **fail** | 甚至显式 `If-None-Match: *` 覆盖已有对象也成功，省略条件头同样成功 |
| 可信 SHA256 | **fail** | 错误单次校验被接受，分片响应及 HEAD 缺校验字段；ETag 不作为替代 |
| Versioning、生命周期配置 | **fail** | 实际查询返回 NotImplemented，无法验证所需回收语义 |
| CORS | 未配置、浏览器 pending | 实际查询 NoSuchCORSConfiguration |
| 短期权限隔离和到期 | pending | 数据功能模式没有 STS，不执行或伪报权限拒绝结果 |

机器报告分别为 [juicefs-report.json](juicefs-report.json)（实际 STS 尝试）和 [juicefs-data-report.json](juicefs-data-report.json)（service-only 数据功能检查）。两个报告均为 fail；各自未执行项保留 pending。

## 运行与清理

探针入口、模板和步骤见 [验证指南](README.md)。CLI、Ruff lint/format、Python 编译与 JSON 模板解析已通过。每轮只操作自身 UUID key 和 UploadId，完成的轮次执行删除及中止，HEAD 确认对象不存在。真实异步生命周期、浏览器、外网直传、集群跨入口并发条件写及 Go Adapter context 取消仍需补验。

最初原生 STS 请求遗漏 `x-amz-content-sha256`，JuiceFS STS 请求最初使用了错误的 SigV4 service；工具均已根据真实标准错误修正。最终能力结论只依据修正后请求，不把探针格式错误当作后端缺口。

到期后请求的原始机器结果保持不改写。近期日志仅做固定失效短语归类，未保存日志原文或 JWT，尚未找到可对应本次请求的确切过期原因；安全检查记录见 [expiration-log-evidence.json](expiration-log-evidence.json)。工具已补充白名单错误原因归类：只有明确 ExpiredToken 或明确过期短语才标 pass，其余拒绝标 pending，绝不把通用 InvalidRequest 直接当作过期证明。
