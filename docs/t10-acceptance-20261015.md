# T10：带文件草稿与完整发布验收

范围：实施计划 T10、系统 Spec #1 的文件草稿/共享引用/大 JSON 条目。T11 Resolve 与 T12 完整交付另行实施。状态：已完成实现、修正及本地验收。

## 实现

草稿直接创建、复制同集合正式版本、保存和删除均接入独立 HTTP/JSON 引用交接。JSON、Annotations、完整文件清单共享 Revision；读取和成功重放返回同一修订快照，更新重放另保留原 appliedRevision。复制版本及发布草稿新增独立 ReferenceID，不复制字节，不修改来源草稿。

同一草稿保留同 FileID 时沿用引用，改路径不产生新引用；替换、移除及删除在本地业务事务中写完整释放任务。删除204仅表示业务删除和释放义务已经持久保存。再次加入已移除文件使用新引用，文件仍须可绑定。同 scope 可跨 Artifact 复用，其他 scope 无权读取或绑定。

有新增引用时先保存固定120秒 attempt 和完整计划，独立 Bind 后最终重检身份、来源及 Revision；失败先持久中止，补偿不早于原准备窗口。未知提交只确认权威数据库，不能凭超时释放成功引用。无新增引用的 JSON 保存、改路径或移除仍在一次本地事务完成。

版本直接发布支持完整多文件/文件夹清单，指定草稿修订发布复制该修订快照。清单按路径排序并拒绝重复路径、重复 FileID 和非法相对路径；MaxFilesPerVersion 默认1000，可配置，草稿和版本共用。超过内部单批限制时分批交接，业务清单全量原子提交。配置上限在成功回执之后检查，不破坏原成功重放。

显式大 JSON 文件沿用普通文件契约，payload 不自动转存或回填。最后有效引用释放才进入物理回收；retention 淘汰旧版本保留其他版本和草稿的引用。恢复扫描覆盖创建版本、创建草稿、更新草稿，只中止和清理，不代替客户端提交。空计划中止不产生空释放任务。

## Review

主线程复核修正：早期 CAS 冲突必须持久 aborted；无新增引用保持单一本地事务；空引用计划不创建会永久失败的释放任务；恢复扫描使用实际草稿 operation kind。独立 Standards review 为0项；独立 Spec review 发现首次草稿发布修订冲突未保存 aborted 和固定指纹，已修正并补双库回归。两轴增量复核均为0遗留项。
